01 · Product thesis

把医生的专业影响力，做成可持续的患者教育服务。

从现有内容与拍摄能力出发，将一次专业表达延展为短视频、互动任务、直播答疑和患者回访，形成可持续运营的服务链路。

核心判断

最值得验证的单位是 一次被医生认可、被患者完成并产生后续服务动作的健康教育体验。

✓AI 为医生整理选题、脚本和问题，医生保留专业表达与发布决策。
✓患者通过小测、情景选择和任务反馈，完成从观看到理解的转化。
✓患者问题被结构化进入医生工作台，支持答复、直播和持续教育。

对现有 C 端产品的借力方式

把一次拍摄转化为可持续运营的内容单元：长视频 → 短视频 → 互动卡 → 直播提问 → 回放章节 → 患者随访。

↗内容资产：脚本、画面、字幕、证据、问题、版本统一管理。
↗医生资产：专科标签、专业表达与可复用答复库持续沉淀。
↗患者资产：学习进度、理解盲点、提问和后续服务意向形成连续记录。
02 · Jobs to be done

围绕医生工作流，重新安排三端协作。

医生、患者与内容团队共享同一套内容对象；每个角色都获得与自己工作目标相匹配的工具和反馈。

医生：把一次专业表达，变成一组可信资产。

医生端的核心价值是把专业判断保留在关键节点，把选题整理、脚本编排、患者互动和问题归档交给 AI 协同完成。

01 / 说清选题简报输入疾病、患者误区、目标人群与沟通重点。
02 / 拍好脚本 + 镜头生成口播、B-roll、字幕、停顿和互动节点。
03 / 审核内容审校来源、更新时间、重点结论和需确认项一处呈现。

医生真正会看的指标

首轮采纳率少返工
审核完成效率更聚焦
同一主题复用率可积累
医生工作台定位：专业表达由医生确认，AI 负责内容编辑、互动编排和问题分流。

患者：把“看过”变成“我知道下一步怎么做”。

患者需要适配当前处境的短内容、可验证的理解和清晰的服务入口，知道何时复习、何时提问、何时联系医生。

01 / 找到场景入口按疾病阶段、检查前后、用药或家属角色进入。
02 / 互动小测 + 分支识别理解盲点，给出面向行动的解释与下一步。
03 / 连接问题回流收藏、追问、预约直播或进入医生服务队列。

患者得到的价值

短内容完成率少焦虑
理解小测正确率会行动
服务连接率更及时
游戏化围绕学习进度与理解反馈展开；患者的个体化问题进入医生服务队列，形成连续照护体验。

内容/运营：把一场拍摄，运营成可测量的服务。

运营侧需要主题排期、版本管理、直播编排和复盘看板，让每个素材、患者问题和直播结果都有来源与去向。

01 / 规划主题地图按患者旅程拆解误区、关键行动和内容空白。
02 / 编排资产流水线同一专业内容自动衍生视频、图文、问答与直播卡。
03 / 复盘闭环看板查看理解结果、患者问题和医生响应效率。

运营真正会看的指标

主题到发布时间更快
内容资产复用率更省
直播问题解决率更深
先将拍摄、审核和发布沉淀为可追踪的内容对象，再叠加模型能力，让每一轮投入都能形成可复用资产。

04 · Agent architecture

三个 Agent，协同医生团队的三类工作。

按内容、互动和直播拆分，医生在关键节点确认专业表达，AI 负责把工作流串起来。

AGENT 01 / AUTHOR

科普编导 Agent

把医生的知识、已有视频和选题意图，整理成可拍、可审、可复用的内容包。

  • 选题 brief 与人群/场景拆解
  • 脚本、镜头、字幕、标题多版本
  • 证据卡、重点句、引用与版本
  • 从长视频切片到互动节点建议
输出：医生审核后的内容包

AGENT 02 / COACH

患者陪学 Agent

围绕一条科普内容，生成理解确认、任务和个性化复习，帮助患者完成一次有效学习。

  • 视频中插入小测、拖拽、判断、分支
  • 根据错题解释“为什么”，强化理解
  • 学习进度、收藏、问题和提醒
  • 个体化问题自动进入医生服务队列
输出：患者理解与行动记录

08 · Build order

用 3 个专病或检查试点验证服务价值。

从医生审核、患者理解和问题回流三个节点开始，逐步扩展直播、院内接口和规模化运营。

验证“内容 → 互动 → 回流”

聚焦一个专病或一个高频检查场景，用已有内容与拍摄能力完成最小闭环。

内容科普编导 Agent：brief、脚本、镜头、字幕、来源卡、重点句。
患者互动视频 + 5 道理解题 + 收藏/提问 + 医生审核队列。
验证10 位医生/100 位患者；关注首轮采纳率、完成率、问题分流准确性。

把一次内容变成一条内容流水线

把互动单元、患者进度和直播前后流程接到同一个内容对象上。

产品疾病/阶段内容地图、错题复习、问题聚类、直播流程单和回放生成。
系统医生工作台、内容版本、来源与审核记录、消息与权限。
验证看复用率、医生响应 SLA、患者复访、直播问题沉淀率。

扩展医疗数据和规模化直播

在内容服务闭环稳定后，进入院内接口、机构权限和多医生直播的产品化阶段。

平台对接患者门户、院内系统、标准化健康对象与机构级权限。
直播多医生、多专病、峰值弹性、内容审核、回放和多渠道分发。
协作将临床决策相关需求单独立项，配置外部验证、审计和责任主体。

下一阶段重点关注

聚焦医生审核的科普场景先围绕专病教育、检查准备和术后管理建立高频使用路径，再扩展服务范围。
以理解和行动衡量效果关注理解率、服务连接率和医生重复解释减少量，形成可复盘的业务指标。
建立患者数据协作机制围绕脱敏、权限、告知同意和医生确认设计直播与互动流程。
采用学习成就机制用进度、徽章和复习任务鼓励持续学习，服务患者的专属学习路径。

用“理解和闭环”替代“流量和热闹”。

指标要能帮助产品做取舍，也要能暴露安全问题。任何单一指标都不应单独成为上线依据。

10 · Clinical collaboration

把医生审核与服务分流嵌入产品流程。

通过清晰的内容分级、问题分流和审核记录，让医生始终掌握专业表达、患者连接与服务升级的关键节点。

四级服务分流

Agent 先判断问题类型，再将内容引导至知识学习、行动指导、医生审核或紧急服务入口。

G0 / 知识定义、原理、检查流程、术语解释，展示来源后完成学习。
G1 / 行动一般准备、复习、记录和就医导航，提供条件与下一步。
G2 / 个体化涉及个人报告、用药、症状组合，进入医生审核或真人服务。
G3 / 紧急出现急症线索时优先提示就医，并进入机构设定的紧急服务流程。

可追溯的内容工作流

来源每个医学主张挂来源、日期和适用范围，医生可在审核时快速核对。
审核医生确认内容、重点句和互动答案；系统记录版本、修改人和发布时间。
交互患者清楚当前处于学习、提问还是服务连接阶段，入口始终可见。
复盘记录问题分流、医生覆盖、患者反馈和内容表现，用数据持续优化规则。
试点验证节点：若患者更偏好快速问答、医生更需要内容生产工具，或互动没有带来理解率与服务连接提升，就将产品重心收敛到内容工作台和人工直播工作台。
